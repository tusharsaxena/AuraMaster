# Issues #21 and #23 Implementation Plan

> Run as Workflow orchestration (ultracode): one implementer and one independent reviewer per task,
> then one checkpoint agent per milestone.

**Goal:** Close out two open AuraMaster issues on one branch. Issue #23 removes the leftovers of the
retired sub-pages: the dead `pageDim` path in `settings/Text.lua`, the unreachable `EMPTY_PAGE` in
`settings/OptionsSetup.lua`, and stale "Filters page" / "Text page" wording in player strings, docs
and comments. It changes no behavior. Issue #21 makes the LibKa0s-Schema-1.0 adoption complete and
consistent. The adoption itself already landed on master as `AM-15` (cf91fe1, 2026-09-24) and `AM-16`
(75f2f19), which reversed the v1.55.0 "not now" decision. What is left is to make the library-absent
host arm answer exactly as the library does. Today it disagrees in four places:

- the host Read answers the root itself for a path with no segment past it;
- the host index keeps the LAST row on a duplicate path, where the library keeps the first;
- the host change test compares tables by `FilterCompiler.Signature`, so a color written as `-0`
  over `0` counts as a change;
- the host Validate does not report a duplicate path.

The run also pins the bracket and the JC-9 contract in both builds, and closes the decision record.

**Architecture:** `settings/Schema.lua` picks every primitive once, at file load: the library's
member when `LibStub("LibKa0s-Schema-1.0", true)` answers, the host body otherwise. The live build
(`tests/fresh_env.lua`, the runner) runs the library, and `tests/degraded_env.lua` loads no LibKa0s
and runs the host arm. Each #21 task writes one test that loops over both builds (the `inBuild`
helper in `tests/test_schema.lua`) and fixes the host arm where they differ. `NS.SetByPath`,
`NS.GetSetting`, `NS.CheckWrite` and `NS.ApplyDefault` stay the host's in both builds, as the issue
and `docs/schema.md` ("Write seam: why AuraMaster keeps SetByPath") record.

**Tech Stack:** Lua 5.1 (WoW client), Ace3, LibKa0s v1.61.0 vendored under `libs/LibKa0s/`
(LibKa0s-Schema-1.0 minor 2: `SplitPath`, `Read`, `Write`, `SameValue`, instance `FindRow`, `AddRows`,
`Reindex`, `BulkBegin`, `BulkEnd`, `BulkRun`, `BulkAdd`, `InBulk`, `Validate`; the reference is
`../LibKa0s` tag v1.61.0 `docs/api/Schema/version-2-docs.md`). The headless harness is
`tests/run.lua` with the vendored kit under `tests/_kit/`, plus luacheck and lizard.

## Review Focus

These are the likeliest untested failure modes. Each has a test in the task that owns it, and the
reviewer checks that test first. The list holds seven rather than the usual five on purpose: items
1-5 are the five #21 parity risks, one per library-absent primitive, and items 6-7 are the only two
#23 changes that remove code (the rest of #23 is wording). The run ships two issues on one branch,
and dropping either group would leave one issue's code removals with no named review focus.

1. **The degraded build's Read answers the root for a short path.** `NS.GetSetting("container", 1)`
   returns the whole container table and `NS.GetSetting("")` returns the whole profile without
   LibKa0s, where the live build answers nil. Owned by I21-01, test "schema: a path with no segment
   past its root reads nil, the library's Read and the host's (#21)".
2. **A row added after load on a path already taken answers differently per build.** The host index
   keeps the last row and the library keeps the first. An appended row must also be findable at
   once in both builds. Owned by I21-02, test "schema: a duplicate path answers the first row
   registered, and an appended row answers at once, the library's and the host's (#21)".
3. **The bracket nests, survives a raise and ignores a stray End in the degraded build too.** Depth,
   the error mark and the mute release are pinned today only on the live build
   (`tests/test_bulklog.lua`). A reset act's single line with `info.profileReset` is pinned in both.
   Owned by I21-03, test "schema: the bracket nests, survives a raise and ignores a stray End, the
   library's and the host's (#21)".
4. **SameValue and Signature disagree on a color table.** A color written with a `-0` channel over a
   stored `0` is no change under `SameValue` (live) and a change under `Signature` (degraded), so the
   two builds count a different N on the same bulk act. Owned by I21-04, test "schema: a color with a
   -0 channel over 0 is no change, the library's SameValue and the host's (#21)".
5. **The degraded validator misses a duplicate path.** The library's `Validate` reports it; the host
   loop does not. Owned by I21-05, test "schema: a duplicate path fails validation, the library's and
   the host's (#21)".
6. **A page drawn disabled would still gray the Text section's Preview and cheat sheet** if any of
   the dim path survived the removal. Owned by I23-01, test "text page: the Preview and the cheat
   sheet read the same when the page is drawn disabled; the dim path is gone (#23)".
7. **RenderPage with no container and a per-container spec still draws a strip.** Owned by I23-02,

## Resume

Git is the only state. A task is done when a commit whose subject starts `<ID>: ` exists on
`feat/2026-09-26-issues-21-23` or on master. `<ID>R: ` is that task's review fix. Nothing else,
including this plan's checkboxes, records progress.

```sh
cd /mnt/d/Profile/Users/Tushar/Documents/GIT/AuraMaster
git checkout feat/2026-09-26-issues-21-23
git log --oneline master..feat/2026-09-26-issues-21-23
git log --format=%s master..feat/2026-09-26-issues-21-23 | grep -oE '^I2[13]-[0-9]+R?' | sort -u
git status --short
```

The next task is the first one below, in plan order (I23-01 to I23-05, then I21-01 to I21-06),
whose id has no commit. A dirty tree is that task's interrupted work: read the diff, then finish it
or `git stash push -m "<ID> interrupted"` it. Never discard it. A task with a commit but no
`ka0s-review` note (`git notes --ref=ka0s-review show <sha>` fails) still needs its review. A
milestone is checkpointed when all of these hold:

- its row is in `docs/superpowers/plans/2026-09-26-issues-21-23.checkpoints.tsv`;
- the local `Checkpoint Mn:` commit exists, and `origin` has it:
  `c=$(git log -1 --format=%H --grep='^Checkpoint M1:' feat/2026-09-26-issues-21-23)` (M2 likewise),
  then `git merge-base --is-ancestor "$c" "$(git ls-remote origin refs/heads/feat/2026-09-26-issues-21-23 | cut -f1)"`
  exits 0. The row's own sha is the head *before* the log commit, so it is never the remote head;
  compare against the `Checkpoint Mn:` commit, never against the row;
- the notes are on `origin`: `git ls-remote origin refs/notes/ka0s-review` prints the same sha as
  `git rev-parse refs/notes/ka0s-review`.

A checkpoint is interrupted when the `Checkpoint Mn:` commit exists locally but the ancestor check
fails (the branch push did not happen), or the branch is pushed but the notes sha differs (the notes
push did not happen). Resume it by re-running only the missing push from step 5 of the checkpoint;
do not re-run the gate or add a second row. A row with no `Checkpoint Mn:` commit (a dirty tree
holding only the TSV) is an interrupted step 4: re-run the checkpoint from step 1.
